# 동점 순환 배정과 파이프 대기열

## 서버 선택

처리 가능한 서버 중 반올림 전 예상 완료 비용이 가장 낮은 서버를 선택합니다. 최저 비용이 정확히 같은 서버가 여럿일 때만 A→B→C 순환 포인터를 사용합니다. 더 비싼 서버는 순환 대상에 넣지 않으며, 화면의 소수점 둘째 자리 값만 같다는 이유로 동점 처리하지 않습니다. 포인터는 방문자별 시뮬레이터에 저장되고 초기화 시 A부터 시작합니다.

결정 기록의 `tie_servers`, `selection_reason`으로 이유를 표시합니다. 원본의 동시 도착 순서, 출력 예측, 실제 출력 비공개 조건은 유지합니다.

## 도착 집계

`latest_arrival`은 마지막으로 처리한 같은 시각 요청 묶음의 도착·즉시 시작·대기 진입·거절 건수입니다. 네 분류를 혼동하지 않도록 도착 당시 내역과 현재 실행·대기 건수를 따로 표시합니다. 도착 건수 = 즉시 시작 + 대기 진입 + 거절입니다. 폴링 사이 여러 묶음이 지나면 가장 최근 묶음을 표시합니다.

## 대기 점

API는 서버별 `queued_requests`에 FIFO 순서의 요청 ID와 입력 토큰을 제공합니다(응답은 앞 32건까지, 실제 큐는 제한하지 않음). 화면은 요청 ID를 키로 사용해 연결선 끝에서부터 18, 38, 58… 위치에 줄을 세웁니다. 앞 요청이 처리 단계에 들어가면 점이 서버 입구로 이동하고 뒤 점이 한 칸 앞으로 갑니다. 폴링 사이 완료되어 사라진 요청도 짧은 퇴장 모션으로 정리합니다. 장식 이동 시간은 실제 처리 시간이 아닙니다.

짧은 B 선에는 3개, A/C에는 각 18개까지 겹치지 않게 표시합니다. 생략된 요청 수는 `+N`으로 표시하며 서버별 대기 건수에는 전체 큐를 표시합니다. 중지하면 이동과 입력 패킷도 정지합니다. 새 도착 패킷은 공통 입력 선에서 한 번에 하나씩 이동하며, 과거 로그 전체를 반복해서 새 도착으로 표시하지 않습니다. 기존 한 요청 상세 시연은 별도로 유지합니다.

### 원형 렌더링 보정

연결선은 카드 위치에 맞춰 가로로 늘어나지만, 점·테두리·대기 라벨에는 실제 캔버스 너비의 역배율을 적용합니다. ResizeObserver로 모바일 내부 가로 스크롤 및 화면 크기 변경도 반영합니다. 대기 점의 가로·세로 크기는 10×10 CSS px, 입력 점은 8×8px입니다. 흐릿한 drop-shadow는 제거했습니다. 1600px 및 390px 뷰포트에서 DOM 크기를 측정했고 공개 사이트에서도 10×10px을 확인했습니다. 프런트 보정 배포는 `20261023T153115Z-6ca929db`이며 백엔드 재시작은 없습니다.

## 검증 및 배포

- Python 테스트 33개, Node 테스트 10개 통과.
- 전체 평가 1,805건 재생: 정상 유입 9배 간격, 최대 대기 A/B/C = 8/9/8건, 완료 1,671건, 한도 초과 거절 134건. 원본 유입 모드도 끝까지 완료함.
- 백엔드 `20261024-queue`, 이전 `20261023-pacing` 보관. 재시작에 따라 기존 메모리 세션은 초기화됨.
- 프런트 `20261023T152513Z-13d23baa` (2026-10-24 KST). 공개 자산 4개 SHA256 일치. HTML은 기존 Cloudflare Insights 삽입만 제외하면 로컬 원본과 일치. 자동 도구의 원시 HTML 해시 차이·일부 UA 403은 기존 CDN 동작이며 보안 설정을 바꾸지 않음.
