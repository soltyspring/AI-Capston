최신 변경(사용자 요청에 따른 복원): 토큰·대기 숫자는 650ms, 서버 비용은 1초(120ms 간격), 확인 단계는 각 850ms, 비교는 1.5초로 되돌렸습니다. ‘다음 서버보다 N초 빠름’ 배지는 제거했습니다. 설명은 밸런서 오른쪽의 별도 메시지 박스에서 400ms 펼침 효과로 표시합니다. 이 효과는 계산 단계의 진행 조건이 아니며, 모바일에서는 흐름도 위로 쌓습니다. 접근성의 동작 줄이기 설정에서는 펼침 효과를 생략합니다.

현재 프런트 `20261023T160042Z-bc79a5fc` (2026-10-24 KST), Node 테스트 13개 통과. 공개 브라우저에서 옆 설명·기존 배지 제거·빠른 단계 전환을 확인했습니다. 백엔드 재시작은 없습니다. 아래는 이전 변경 이력입니다.

최신 보완: 숫자 증가를 사실값 1.4초, 비용 2.4초(서버별 180ms 간격)로 늦추고 각 단계에도 완료값을 읽을 여유를 추가했습니다. 완료는 3.5초 유지한 뒤 실시간 구간으로 넘어갑니다. 상태 카드는 흐름도 오른쪽 위 빈 공간으로 이동했으며 1200px 이하에서는 흐름도 바로 위에 한 줄 카드로 배치합니다.

선택 직후 비교 카드 아래에 짧은 선택 이유를 표시합니다. 처리 가능한 다른 서버 중 차선 비용과 비교해 ‘다음 서버보다 N초 빠름’, 정확한 동점이면 ‘최저 비용 동점 · A/B/C 순환 배정’, 유일한 가능 서버이면 해당 이유를 표시합니다. 지연 감소의 실제 측정 성과가 아니라 해당 결정의 **예상 비용 차이**입니다.

현재 프런트 배포: `20261023T154820Z-e2c07fc4` (2026-10-24 KST). Node 테스트 13개 통과. 아래 시간·배치·배포 내역은 이전 단계의 기록입니다.

현재 화면 제목은 **실시간 요청 분배**입니다. 단계 안내는 상단의 작은 문구 대신 로드밸런서 위 상태 카드에 표시하며 완료 시 초록 배경·체크·선택 서버·요청 ID를 표시합니다. 모바일에서는 상태 카드가 가운데에 보입니다.

숫자 연출: 입력·예상 출력·선택 시 대기 건수는 각 확인 단계에서 0부터 실제 결정 기록값까지 650ms 동안 증가합니다. A/B/C 예상 완료 시간은 비교 단계에서 0.00초부터 1초 동안 증가하며 120ms 간격으로 시작합니다. 단순 표시용 보간으로 라우팅 비용이나 선택 결과를 변경하지 않습니다. 정지/재개와 질문 전환 시 초기화는 동일한 프레임 시계를 따릅니다. 확인 전에는 대시, 확인 후에는 체크와 최종값을 표시하며 실제 0건도 그대로 표시합니다.

숫자 연출 검증 포함 Node 테스트 11개 통과. 공개 브라우저에서 연속 조회한 비용 증가와 완료 상태 카드, 모바일 375px에서 상태 카드가 47~327px 범위에 표시되는 것을 확인했습니다. 프런트 `20261023T154006Z-148a72b0` 배포(2026-10-24 KST), 백엔드 재시작 없음. 아래 이전 배포 기록은 당시 검증 내역입니다.

기존 고정 설명 카드와 독립적인 단계 타이머를 대신해 `RequestStory.jsx`에서 하나의 요청을 추적합니다.

진행 순서: 한 글자씩 입력 → 로드밸런서로 이동 → 입력 토큰 → 예상 출력 → 대기 작업 → 서버 비용 비교 → 선택 서버로 이동 → 처리 → 완료 결과 → 실시간 흐름.

- 예시 문장은 설명용입니다. Mooncake에 질문 원문이 있는 것처럼 표시하지 않습니다.
- 질문 5개를 순환하며 질문마다 아직 시연하지 않은 배정 성공 기록을 연결합니다. 가능하면 토큰 수와 선택 서버가 다른 기록을 우선하지만, 선택 결과를 임의로 바꾸지는 않습니다. 새 기록이 없으면 입력 단계에서 기다립니다.
- 연결한 요청의 비교값과 선택 서버는 완료 및 다음 질문 전까지 고정됩니다. 실시간 구간에서도 다른 요청의 수치로 바뀌지 않습니다.
- 서버별 비용·입력·예상 출력은 해당 요청의 실제 결정 기록에서 읽습니다. 임의의 비교 수치나 학습된 가중치를 만들지 않습니다.
- 점이 선택 서버에 도착하면 별도 시연 진행률이 20ms마다 1%씩, 약 2초 동안 0→100%로 증가합니다. 실제 처리 지연과 별개인 빠른 재현임을 표시합니다. 중지 시 정지하고 재개 시 이어갑니다.
- 처리 단계는 시연 진행률 100% 및 해당 요청의 실제 완료 이벤트가 모두 확인되어야 끝납니다. 실제 출력·지연 역시 그 이벤트에서 표시합니다.
- 완료가 먼저 기록된 경우 ‘완료된 요청의 처리 과정 재현’으로 표시합니다. 연출 시간과 실제 처리 지연은 다릅니다.
- 선분 길이 기준으로 점의 좌표를 계산해 꺾인 연결선을 따라 이동합니다. 첫 시연이 끝나면 기존 실시간 요청 점으로 전환합니다.
- `중지`는 API 재생뿐 아니라 시연 시계·CSS 동작·SVG 모션을 함께 멈춥니다. `시작`은 정지한 단계부터 이어갑니다.
- 시연 완료 후 실시간 흐름을 2초 보여주고 다음 질문으로 자동 전환합니다. `다시 시연`도 지원합니다. 브라우저가 백그라운드에서 돌아왔을 때 긴 프레임 간격으로 단계를 건너뛰지 않도록 한 번에 200ms까지만 진행합니다.
- 좁은 화면의 흐름도는 내부 가로 스크롤을 지원하며 페이지 전체가 옆으로 넘치지 않게 합니다. 동작 줄이기 환경에서는 장식적인 깜박임·전환 효과를 줄입니다.
