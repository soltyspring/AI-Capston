# Mooncake 출력 토큰 예측

실제 GPU 상시 실험 기록으로 학습한 모델은 [출력 토큰 예측 모델 개선 및 학습 기록](output-prediction-improvement.md)에서 설명합니다.

고정 400토큰 대신 과거 요청 기록으로 학습한 랜덤 포레스트 회귀 모델을 사용합니다.
기본 실행 시 자동 학습하며 기존 `AICAP_TRAIN=1` 환경 설정은 그대로 호환됩니다.

## 재현

```bash
pip install -r backend/requirements.txt
python -m backend.dataset
python -m backend.prediction data/conversation_trace.jsonl
python -m backend.experiment data/conversation_trace.jsonl
```

2026-10-15, 고정 버전 Conversation 12,031개 기준:

- 시간순 학습: 8,421개 (마지막 도착 시각 2,553,000ms)
- 검증: 1,805개. 학습에 사용하지 않으며 고정 설정 모델 평가용입니다.
- 테스트/대시보드 재생: 1,805개 (첫 도착 시각 3,048,000ms)
- 캐시는 재생 시작 시 비어 있습니다.

특징: 입력 토큰 수, log(1+입력 토큰 수), 512토큰 블록 수, 학습 구간에서 첫 블록 식별자가 등장한 횟수.
블록 식별자는 의미를 나타내는 단어가 아닙니다. 등장 횟수는 학습 구간 입력에서만 집계하고,
미지 접두부는 빈도 0으로 처리합니다. 정답은 실제 출력 길이입니다. 원문 내용은 없습니다.

모델: RandomForestRegressor, 트리 80개, 최대 깊이 8, 최소 리프 20, seed 42, CPU 단일 작업.
예측값 범위는 1~2,048토큰입니다. 시작 시 학습하며 외부 pickle 모델은 로드하지 않습니다.
테스트 요청은 입력 특징으로만 일괄 예측·캐시합니다. 테스트 출력은 이 예측 과정에서 읽지 않습니다.

## 예측 오차 (토큰)

| 방식 | 검증 MAE | 테스트 MAE | 테스트 RMSE |
|---|---:|---:|---:|
| 고정 400 | 186.20 | 185.73 | 247.34 |
| 학습 구간 평균 346 | 179.30 | 179.31 | 238.62 |
| 랜덤 포레스트 | 179.55 | 178.05 | 237.99 |

검증 MAE에서는 학습 평균 기준선이 모델보다 조금 낫습니다. 테스트에서는 모델이 조금 낫지만
한 시간 트레이스의 단일 시간 분할이므로 강한 일반화나 큰 성능 향상을 주장할 수 없습니다.
설정을 테스트 결과에 맞춰 반복 튜닝하지 않았습니다. 모델 선택·추가 튜닝은 검증 구간에서 해야 합니다.

## 라우터 연결

예상 출력은 `Simulator.route`에서 한 번 계산하고 모든 서버 후보에 동일하게 전달합니다.
후보별 답변 생성 시간 = 예측 토큰 / 해당 서버 생성 속도.
최종 비용 = 기존 작업의 예상 대기 + 캐시 제외 입력 처리 + 예상 답변 생성.
이 비용으로 선택하며, 배정된 작업의 예상 완료 시각과 진행률에도 같은 예측을 씁니다.

실제 출력은 시뮬레이터의 실제 완료 시각 계산과 완료 이후 오차 집계에만 사용합니다.
거절 요청은 실시간 완료 MAE에 포함하지 않습니다. 오프라인 테스트 MAE는 전체 테스트 요청 기준입니다.
공통 모델을 동일한 3개 서버에 배치했다는 가정이므로 입력당 출력 예측값은 서버별로 같고 처리 속도/대기만 다릅니다.
예측값이 달라도 특정 요청의 선택 서버는 같을 수 있으며, 라우팅 성능 개선은 별도로 검증해야 합니다.

동일한 가상 서버 설정으로 다시 비교한 평균 완료 지연은 Round Robin 1230.45초,
학습 예측 기반 최소 비용 정책 1229.65초였습니다. 개선 폭은 약 0.07%로 작아 큰 분배 성능 향상을 주장하지 않습니다.

지도학습이지 자기지도학습·강화학습·온라인 자율 재학습은 아닙니다.
